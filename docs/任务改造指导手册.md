# doc_audit_web 任务改造指导手册

面向要在此服务上构建自己任务（校核、提取、比对、格式化……）的开发者。
原则一句话：**壳不动，芯可换；参数进配置，逻辑进模板**。

---

## 1. 架构分层：什么能改，什么别碰

```
        ┌──────────── 壳（任务无关，一般不改）────────────┐
  上传 → web/app.py（API/校验）→ web/worker.py（串行队列）  │
        → web/db.py（任务状态）→ 轮询/下载接口              │
        └──────────────────┬───────────────────────────┘
                           │ settings dict 一路向下
        ┌──────────────────┴─────────── 芯（你的任务）────┐
        │ doc_audit/runner.py  one-shot 执行循环          │
        │ config/prompts.yaml  任务逻辑（唯一入口）        │
        │ config/settings.yaml 全部参数                   │
        │ config/gateway.patch.yml 网关路由模板           │
        └──────────────────────────────────────────────┘
```

数据流：`settings.yaml → config.py（${ENV} 展开 → paths 解析 → patch 渲染 → prompts 加载）→ Runner（拼 prompt）→ build_harness（SDK 参数全来自 settings）→ agent 在任务 workspace 内自主执行 → final_response → _parse_report → audit_report.json`。

代码中已无硬编码参数：改行为不需要改 .py，只有改变"执行方式"（如加超时重试、多轮会话）才需要动 runner.py / llm.py。

## 2. 配置文件速查

| 文件 | 内容 | 改动频率 |
|------|------|----------|
| `config/settings.yaml` | SDK 参数（model/provider/reasoning_effort/max_tokens/context_window/profile/超时/协议开关）、server、limits、paths、prompt_vars | 高 |
| `.env`（gitignore） | `GATEWAY_API_KEY`、`GATEWAY_BASE_URL` | 换密钥时 |
| `config/prompts.yaml` | 各 mode 的任务模板 | **做新任务就改它** |
| `config/gateway.patch.yml` | provider 路由模板（占位符自动填充） | 极低（换协议时） |
| `config/_generated/` | 渲染产物，勿手改、勿提交 | — |

`settings.yaml` 中 `${VAR}` 会展开为环境变量（`${VAR:默认值}` 可带默认）；`paths.*` 相对项目根自动转绝对。

## 3. Prompt 模板规则（最容易踩坑处）

- 占位符是 `<<token>>` **字符串替换，不是 format**——JSON 示例里的花括号随便写，无需 `{{` 转义。
- 可用 token：`<<workspace>>`（任务绝对路径）、`<<file_types>>`（来自 limits.allowed_exts）、`<<min_confidence>>`、`<<constraint>>`。新增 token：改 `runner.py:_render_prompt` 的传参 + settings.prompt_vars，模板里直接用。
- **输出合同必须保留**：模板末尾要有"最终回复必须且只能是一个合法 JSON 对象"（`<<constraint>>` 已内置）。实测教训：multi/high 档曾出现 agent 干完活但最后回了一段散文，报告只能落进 `{error, raw_response}` 兜底。
- agent 只看到 workspace 路径字符串，文件都在里面；写新任务时记得同时改 `limits.allowed_exts`，否则文件传不进来。

## 4. 常见改造配方

### 配方 A：换一种任务（只做摘要 / 参数提取 / 完整性检查）
1. `config/prompts.yaml` 复制一份现有模板改内容和输出 JSON 示例；
2. `settings.yaml` 调整 `limits.allowed_exts`；
3. 完成。worker/app/db 零改动——报告 dict 原样透传，前端拿到什么格式取决于你模板第 5 步的 JSON 示例。

### 配方 B：新增一个 mode（如 `extract`，与 single/multi 并存）
1. `prompts.yaml` 加顶层键 `extract: |...`；
2. 无需注册——`app.py` 的合法 mode 列表、`runner.py` 的 mode 校验都直接读模板键；
3. 提交时 `curl -F "mode=extract" ...` 即可。

### 配方 C：输出结构变了，前端/下载要配合
报告文件是 workspace 里的 `audit_report.json`（文件名可经 `limits.report_filename` 改——注意它是**文件名不是路径**，`paths.*` 分组的值会被自动解析成绝对路径，别放错组，否则报告会写到项目根）。`/api/tasks/{id}/report` 原样返回该文件；若要在 API 层做转换/摘要，改 `app.py:download_report`；若要任务列表页显示新字段，改 `create_task`/查询接口。JSON 解析容错逻辑在 `runner.py:_parse_report`（去围栏 → 整体 loads → 首 `{` 尾 `}` 回退 → error dict），一般不用动。

### 配方 D：挂自己的 skill（按工作流步骤执行）
dsh 运行时原生扫描会话 cwd 下的 `.dsh/skills/` 与 `.agents/skills/`，格式为 `<name>/SKILL.md`（frontmatter: name/description + 正文步骤，可带 `scripts/`、`references/`）。接入方式：
1. 建 `data/skills_library/<name>/SKILL.md`；
2. 在 `worker.py` 出队处（`runner = Runner(...)` 之前）加两行把 skills_library 拷进 `workspace/.dsh/skills/`；
3. prompt 模板里写"使用 `<<skill 名>>` 完成第 2 步"，agent 会按需加载正文（不占常驻 prompt）。
边界：skill 管"怎么做"，prompt 末段管"输出成什么样"——输出合同仍要留在 prompt 里。

### 配方 E：换模型 / 换网关
只改 `settings.yaml`：`model`（patch 模板会自动重新渲染，不再需要同步改第二个文件）；换网关改 `.env` 的 `GATEWAY_BASE_URL` + `api_style`（openai-completions / anthropic-messages）。第三方网关务必保持 `supports_developer_role: false`，否则网关 400。

## 5. 任务执行模型（决定你能要求 agent 做什么）

- **one-shot**：一个会话、一次 `harness.run`，agent 在会话内自主多轮（读文件→分析→写文件→验证→收尾 JSON）。复杂流程写进步骤清单即可，不需要拆 pipeline。
- 每任务独立 workspace + 独立 session（`task-{id}` 前缀），互不污染；worker 单线程串行，长任务会排队——并发需求改 `worker.py` 线程数。
- 时长预期（20×40KB 级文档实测）：flash 级模型 40–100s（single）/ 150–260s（multi），大模型可到 200s+。脚本侧轮询超时见各测试脚本的 330s/600s 上限。
- agent 修改文件后，用户可经 `/api/tasks/{id}/files/{filename}` 下载产物；prompt 里"改前必读、改后必验、失败记 skipped"是保留项。

## 6. 上线前检查清单

1. **静态**：`python -c "from doc_audit.config import load_config; s=load_config(); print(s['model'], s['prompt_templates'].keys())"` ——配置能加载、模板能发现。
2. **冒烟**（60s 内）：直接 `build_harness` 发一个"回复 {\"ok\": true}"，验证网关路由/配额（403 insufficient_quota 是账户问题不是代码问题）。
3. **e2e**：起 `main.py` → 提交真实样本 → `completed` → 报告 JSON 合法、预埋问题命中。
4. **密钥扫描**：`settings.yaml`、`prompts.yaml`、生成的 patch、全部 .py 中不得出现 `sk-`；`.env` 在 `.gitignore` 内。
5. **Windows 沙箱**：`data/` 需当前用户完全控制权限，否则 ACL 报错：
   `icacls data /grant %USERNAME%:(OI)(CI)F`（经 PowerShell 执行）。

## 7. 故障速查

| 症状 | 根因 | 处置 |
|------|------|------|
| 报告是 `{error, raw_response}` 且 `raw_response` 为空 | 网关 403 配额耗尽 / 路由失败 | 看 events 里 `assistant/attempt` 的 error；充值或关"仅免费额度" |
| `raw_response` 是散文 | 输出合同没被遵守 | 模板末段保留 `<<constraint>>`，或降 reasoning_effort 试验 |
| harness 初始化 404 | 协议不匹配 | `api_style` 与网关实际协议核对 |
| 400 developer role | 网关拒绝 | `supports_developer_role: false` |
| 任务 completed 但 agent 说没权限写文件 | 沙箱 ACL | 见检查清单第 5 条 |
| mode 400 报错 | 模板键与提交值不符 | `prompts.yaml` 顶层键即合法 mode 列表 |

## 8. 测试脚本（`data/` 下，可复用）

`try_models.py` 模型横评、`try_reasoning.py` 思考档矩阵、`rep_flash.py` / `rep_flash_multi.py` 单模型复测——都遵循同一模式：改配置 → 起服务 → 提交 → 轮询计时 → 命中检查 → 恢复基线。做新任务时照抄一个改 prompt/文件/判定条件即可。注意这些脚本历史上会直接改 `settings.yaml` 的 model 行，新版格式（带引号）兼容。
