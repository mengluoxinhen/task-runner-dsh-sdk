# task-runner 任务接入与改造手册

原则：**壳不动，芯可换；任务进注册表，逻辑进提示词，参数进配置。**

---

## 1. 架构分层

```
        ┌──────────── 壳（任务无关，一般不改）────────────┐
  上传 → web/app.py（API/校验/sync 等待）                │
        → web/worker.py（并发队列/优先级/完成事件）       │
        → web/db.py（任务状态）→ 轮询/结果/文件下载       │
        └──────────────────┬───────────────────────────┘
                           │ settings + TaskSpec 一路向下
        ┌──────────────────┴─────────── 任务定义 ───────┐
        │ config/tasks.yaml   任务注册表                 │
        │ config/prompts/*.md 每个任务的提示词           │
        │ task_engine/tasks.py 加载与校验                │
        │ task_engine/runner.py 执行 + 产物校验          │
        └──────────────────────────────────────────────┘
```

请求流：`POST /api/tasks/{task_type}` → 校验扩展名/数量/大小 → 建 workspace 存输入 → 入队 → Runner 渲染 prompt、起 harness → Agent 在 workspace 内执行 → 写 `result.json` 和/或 `output/` → Worker 校验并落库 → 轮询到 completed → 结果从 `result.json` 现读返回。

代码中不再有任务语义：改任务只改 `tasks.yaml` + `prompts/*.md`。只有改变“执行方式”（超时、并发、结果打包）才动 `runner.py` / `worker.py` / `app.py`。

## 2. 任务注册表（config/tasks.yaml）

```yaml
defaults:                      # 所有任务的默认值，任务条目可覆盖
  delivery: async              # async | sync
  agent_timeout_seconds: 900   # 单任务 Agent 硬超时
  sync_timeout_seconds: 300    # sync 请求最长等待，超时退化为 202
  max_file_bytes: 52428800     # 单文件上传上限
  output:
    kind: json                 # json | files
    file: result.json          # Agent 最终 JSON 文件名

tasks:
  <task_id>:
    name: 展示名
    description: 给前端看的说明
    accept: [".docx", ".pdf"]  # 该任务允许的输入格式
    min_files: 1
    max_files: 5
    prompt: <prompt 文件名>     # 相对 config/prompts/
    delivery: async | sync
    output:
      kind: json | files
      file: result.json
      dir: output              # 仅 files：产物目录（安全相对路径）
      allowed_exts: [".md"]    # 仅 files：允许的产物格式
      min_files: 1             # 仅 files：产物数量下限
      max_files: 20            # 仅 files：产物数量上限
      max_total_bytes: 209715200  # 仅 files：产物总大小上限
```

`task_id` 必须匹配 `[a-z0-9_]{1,64}`。启动时会聚合校验：扩展名、数量、prompt 文件存在、`output.dir` 安全、`output.file` 只能是文件名、`delivery`/`output.kind` 合法。配置有错会拒绝启动并一次列出全部问题。

## 3. 提示词规则（最容易踩坑）

- 占位符是 `<<token>>` **字符串替换**，不是 format：JSON 示例里的花括号无需转义。
- 可用 token：`<<workspace>>`（任务绝对路径）、`<<task_name>>`、`<<file_types>>`（accept 拼接）、`<<input_files>>`（本次输入文件名）、`<<output_dir>>`（files 任务的产物目录）、`<<constraint>>`（全局输出合同）。
- **输出合同必须保留**：提示词末尾要有“最终回复必须且只能是一个合法 JSON 对象”（`<<constraint>>` 已内置）。
- 明确要求 Agent 把最终 JSON **写入 `<<workspace>>/result.json`**，而不只是在回复里输出。服务端会校验该文件；json 任务缺失时回退解析 final_response，仍失败则任务 failed。
- files 任务必须明确“产物写到 `<<workspace>>/<<output_dir>>/`”，并在结束时写 `result.json` 摘要（可选，服务端可合成）。
- agent 只看到 workspace 路径字符串，文件都在里面；新增任务时同步改 `accept`，否则文件传不进来。

## 4. 结果合同

### JSON 任务

- `result.json` 是唯一权威结果文件，服务端校验后原子写回（tmp + `os.replace`）。
- 轮询 `GET /api/tasks/{id}` 到 completed 时，`result.data` 是现读的 JSON 本体；`GET /result` 可重复取，`?download=1` 下载。
- 文件被删除/损坏：状态仍 completed，但 `result.available=false`，`/result` 404；不会抛 500。

### 文件任务

- 产物在 `workspace/<output.dir>/`；服务端只收集 `allowed_exts` 内的普通文件，校验数量、非空、总大小。
- 无产物 → failed；`result.json` 摘要缺失/非法时用产物清单合成，不会因为最终回复是散文而误判失败。
- `/result`：单文件直返（按 mimetype），多文件现场 zip；zip 写临时目录并自动删除。

## 5. 交付模式

| 模式 | 行为 | 适用 |
|---|---|---|
| `async` | `POST` 返回 `202 {task_id,status_url,result_url}`，前端轮询 `GET /api/tasks/{id}` | 大多数任务、长任务 |
| `sync` | `POST` 阻塞到完成，直接返回结果（JSON 任务=JSON 本体；文件任务=文件/zip，带 `X-Task-Id`） | 短任务、希望一次调用拿结果 |

sync 细节：

- 等待超过 `sync_timeout_seconds` 或同时等待名额已满 → 返回 `202`，**任务不会取消**，改轮询即可。
- sync 任务在队列中优先出队（并发位满时仍需等待）。
- sync 等待使用独立线程池 + 信号量，不阻塞事件循环。

## 6. 常见改造配方

### 配方 A：新增一个 JSON 任务
1. `config/prompts/extract_fields.md` 写提示词，末尾要求写 `result.json`；
2. `config/tasks.yaml` 加条目：`accept`、`min/max_files`、`prompt`、`output.kind: json`；
3. 重启。`POST /api/tasks/extract_fields` 可用。

### 配方 B：新增一个文件任务
1. 提示词明确产物写入 `<<output_dir>>/`，例如每个输入一个 `.md`；
2. `tasks.yaml` 配 `output.kind: files`、`dir`、`allowed_exts`、数量上下限；
3. 选 `async`（推荐）或 `sync`。

### 配方 C：换模型 / 换网关
只改 `settings.yaml`：`model`（patch 自动重渲染）；换网关改 `.env` 的 `GATEWAY_BASE_URL` + `api_style`。第三方网关保持 `supports_developer_role: false`。任务级不覆盖 model（avoid 全局 patch 状态竞争）。

### 配方 D：调超时/并发
- 单任务硬超时：`tasks.yaml` 的 `agent_timeout_seconds`；
- sync 等待上限：`sync_timeout_seconds`；
- 同时等待的 sync 请求数：`settings.yaml` 的 `server.sync_max_waiters`；
- worker 并发由 `settings.yaml` 的 `agent.max_concurrency`（环境变量 `TASK_MAX_CONCURRENCY`）控制，默认 2，服务内所有用户共享；按 CPU/网关并发能力调整，建议不超过 4。

## 7. 沙箱与 Office skill

- 运行时自带 `office` / `office-docx` / `office-pptx` / `office-xlsx` 等 skill。提示词里应要求 Agent **先加载对应 skill，并调用 `load_workspace_dependencies` 拿到 Python 与自带库**。
- **禁止 pip install**，也不要让 Agent 寻找系统 Python；宿主 `requirements.txt` 里的库只用于本地样例生成/兜底。
- 脚本命名要有业务含义：`extract_pptx.py`、`convert_to_markdown.py`；避免 `inspect.py`、`docx.py`、`pptx.py`、`zipfile.py` 这类遮蔽标准库的名字。
- 沙箱只能写任务 workspace；`data/` 需要 ACL 授权（见第 10 节）。

## 8. 执行模型与超时

- one-shot：一个会话、一次 `harness.run`，Agent 在会话内自主多轮（读文件→处理→写结果→验证→收尾 JSON）。
- 每个任务独立 workspace + 独立 session（`task-{id}`）；worker 按 `agent.max_concurrency` 并发执行（默认 2）。
- `Session.run` 没有超时（阻塞在 `subscription.next()`）。Runner 用 watchdog 线程到点 `harness.close()`，阻塞调用会抛 `TransportClosedError`，任务转 failed。
- 空 `final_response` 且没有 `result.json` 时，错误信息会带 finish_reason、最后一个 error event 和“疑似网关 403 配额/路由”提示。

## 9. API 速查

| 方法/路径 | 说明 |
|---|---|
| `GET /` | 服务信息/端点 |
| `GET /health` | 健康检查 |
| `GET /api/task-types` | 任务元数据 |
| `POST /api/tasks/{task_type}` | multipart `files`，任务类型在路径 |
| `GET /api/tasks?task_type=&status=&limit=&offset=` | 列表 |
| `GET /api/tasks/{id}` | 状态；completed 的 JSON 任务内联 `result.data` |
| `GET /api/tasks/{id}/result[?download=1]` | JSON 或文件/zip |
| `GET /api/tasks/{id}/files/{path}` | workspace 内文件（含 `output/` 子目录） |
| `POST /api/tasks` | 410（旧接口已移除） |

错误体：`{"detail":{"code":"...","message":"..."}}`；常见 code：`unsupported_ext`、`too_many_files`、`too_few_files`、`file_too_large`、`unknown_task_type`、`task_not_completed`、`task_failed`、`result_missing`、`path_forbidden`。

## 10. 上线前检查清单

1. **静态**：`python -c "from task_engine.config import load_config; from task_engine.tasks import load_tasks; print(list(load_tasks(load_config())))"` —— 配置能加载、任务能发现。
2. **接口测试**：`python tests/test_api.py` —— 校验、轮询内联结果、zip、sync 超时、迁移、路径安全。
3. **冒烟**：起服务 → `POST /api/tasks/ppt_extract`（或你的短任务）→ 200/202 → 结果 JSON 合法。
4. **密钥扫描**：`settings.yaml`、`tasks.yaml`、`prompts/*.md`、生成的 patch、全部 `.py` 中不得出现 `sk-`；`.env` 在 `.gitignore` 内。
5. **Windows 沙箱**：`icacls data /grant %USERNAME%:(OI)(CI)F`。
6. **单进程**：`main.py` 固定 `workers=1`；并发由进程内 worker 线程池实现，不要用多 uvicorn worker 部署（queue/Event 不跨进程）。

## 11. 故障速查

| 症状 | 根因 | 处置 |
|---|---|---|
| 任务秒失败，错误含“疑似网关 403 配额/路由” | 网关配额耗尽/路由失败 | 查网关控制台；核对 `.env` 与 `settings.yaml` 的 model/provider |
| `result.json` 解析失败 | 输出合同没被遵守 | 提示词末尾保留 `<<constraint>>`，明确写 `result.json` |
| files 任务无产物 | Agent 写到别处/扩展名不符 | 提示词明确 `<<output_dir>>/`；核对 `allowed_exts` |
| harness 初始化 404 | 协议不匹配 | `api_style` 与网关协议核对 |
| 400 developer role | 网关拒绝 | `supports_developer_role: false` |
| 任务 completed 但 Agent 说没权限写 | 沙箱 ACL | 见第 10 节第 5 条 |
| sync 请求返回 202 | 等待超时/名额满 | 用 task_id 轮询；调大 `sync_timeout_seconds` 或 `sync_max_waiters` |
| 下载返回 403 | 路径穿越/符号链接 | 只从任务 workspace 内下载 |

## 12. 安全边界

- 上传名只取 basename，控制字符替换，同名自动编号，保留名加 `input_` 前缀。
- 下载路径 `resolve()` 后必须仍在任务 workspace 内；拒绝目录穿越与符号链接。
- `result.json` / `output/` / `_artifacts/` / `.dsh/` / `__pycache__/` 为保留名，避免与系统产物冲突。
- 单文件上传/结果大小上限在 `settings.yaml.limits`；文件任务产物总大小在 `tasks.yaml.output.max_total_bytes`。
